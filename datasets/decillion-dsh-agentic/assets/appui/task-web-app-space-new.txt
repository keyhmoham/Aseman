You are the software engineer of an Decillion space. Build a new app for BRIEF.md in this directory.

## Hosting: window mode (JOB.json kind: app)
This App UI opens as a **framed desk card window** (title bar, resize, pin).
Design for a desk window and for phones; include the phone widget.
The frontend is WEB (JOB.json ui: web), because the person asked for web
technology: follow AGENTS.md's web rules (Material 3 Expressive via
@material/web unless the brief names another framework, Decillion adaptive
theming, the web OpenUI kit).
Every app also has a phone widget, and it is native: write it as an Elpian
program in elpian/widget/*.js (ELPIAN.md: The phone widget, and A web app's
widget) showing the few live facts that matter for this app's use case.
Your server serves GET /elpian/widget.js; bundle it with
node vendor/decillion-elpian/bundle.mjs . --widget and check it with
node vendor/decillion-elpian/check.mjs elpian/widget.js --widget-only --apps APPS.json --server http://127.0.0.1:8787
(validate its trees with your elpian_validate_program tool, widgetOnly: true,
or node vendor/decillion-elpian/validate.mjs --program elpian/widget.js --widget-only).

You are building this yourself, with your own tools on the space's sandbox:
the shell (execute) and the file tools, in {DIR}. Your elpian_* tools (the
validator and the headless driver named above) are the decillion-elpian command,
with the same names and JSON arguments, run in {DIR}:
  decillion-elpian tools [name]       the tools and their arguments
  decillion-elpian elpian_open '{"server":"http://127.0.0.1:8787"}'
  decillion-elpian elpian_tap '{"target":"Add task"}'   (sessions stay open between commands)
  decillion-elpian elpian_validate @tree.json            (arguments from a file)
  decillion-elpian stop                                  (end the driver sessions)
While you test, run your server in the background
(cd {DIR} && nohup <start command> > server.log 2>&1 &) and stop it when done.

Context files here: AGENTS.md (your rules: follow them), ELPIAN.md (the Elpian
frontend guide and reference), BRIEF.md (+ CHANGES.md),
APPS.json (the space: apps with microtools and their args_schema, and agents —
the only ones the app may use, by those names),
DECILLION_API.md (the exact page API contract), JOB.json (port 8787, dir),
vendor/decillion-sdk/ (decillion.js for the page; server.cjs / server.mjs /
decillion_server.py for your server: use them for every Decillion call),
vendor/decillion-openui/ (agent-backed UI islands).

Work in this order:
1. Plan: list the screens, the data, and for each feature whether it is
   programmed (your server, or a microtool via Decillion.call) or needs an
   agent's judgment (Decillion.ask / askJSON / conversation / an OpenUI island),
   and whether it runs in the page or on your server. Server-side agent and
   app calls use the server SDK: Decillion.fromRequest(req) while serving a
   person (billed to them), Decillion.app() only for work nobody is in front of
   (billed to the person who asked for the app).
   Use only the apps, microtools, argument shapes and agents APPS.json lists,
   by those names, and use them for real: every feature the brief gives to
   an agent or an app calls that agent or app through the Decillion API — never
   a made-up agent or app, a hard-coded reply, a direct model call or a fake
   endpoint standing in for one (mocks belong in tests only). The platform
   checks the code against APPS.json (decillion-wiring-check) before the app is
   ready. If the brief needs an agent or app the space does not have, say so
   in PLAN.md and leave that feature out rather than imitating it.
   Decide what the phone widget shows: the live facts someone checks at a
   glance for this app. Decide the design: the hero of each screen, the

2. Build the fullstack project (frontend + backend) as described above.
3. Test: unit/API tests for your server, the theme applicator, parsing of

6. Call appui_publish with dir {DIR}. The platform verifies the app itself

   opens it as a framed desk window. If it reports a problem, find the root cause, fix it,

Keep everything inside {DIR}. Do not ask questions: decide sensibly and note
assumptions in PLAN.md.
